UCSB-XRP API REFERENCE


SCOPE

This reference defines the public interface used by UCSB-XRP programs. Public
records, supplied services, functions, and constants are imported from
ucsb_xrp. The live-program functions are accessed through ucsb_xrp.live.
Factory functions are imported from course_setup.

The six selectable components have reference and student implementations with
the same public interface. Student templates inherit base classes from
ucsb_xrp.student_api. Those base classes support implementation work but are
not part of the user API described here.

HOW THE PARTS FIT TOGETHER

Robot performs the repeated measurement and control work:

MotionCommand
    -> DifferentialDrive.wheel_speeds()
    -> WheelSpeeds
    -> WheelSpeedController.update()
    -> DriveCommand
    -> XRPBot.set_drive()

XRPBot.read()
    -> RawSensors
    -> SensorModel.update()
    -> Measurements

Measurements.left_increment_mm and right_increment_mm
    -> Odometry.update()
    -> Pose

Robot.step() returns:

RobotState(measurements, pose)

Navigation adds one level above Robot:

NavigationGoal sequence + current Pose
    -> NavigationController.update()
    -> MotionCommand
    -> Robot.step()

Planning supplies the destinations used by navigation:

ArenaMap
    -> OccupancyGrid.from_arena()
    -> GridPlanner.plan()
    -> GridPath
    -> GridPath.to_goals()
    -> NavigationGoal sequence

The supplied DeliveryMission performs the final sequence:

stationary range samples
    -> selected map condition
    -> OccupancyGrid
    -> GridPath
    -> NavigationGoal sequence
    -> navigation to the destination


COMMON CONVENTIONS

Units

- Distances, positions, wheel travel, map coordinates, and grid resolution are
  in millimeters.
- Linear speed and wheel speed are in millimeters per second.
- Hardware timestamps are integer milliseconds.
- Elapsed time used in calculations is in seconds.
- Heading and heading change are in radians.
- Turn rate is in radians per second.
- Each left/right drive command is dimensionless and limited by
  RobotConfig.max_drive_command.

World coordinates

- Positive x is the reference forward direction.
- Positive y is to the left of positive x.
- Heading zero points along positive x.
- Positive heading and positive turn rate are counterclockwise.

Robot directions

- Positive forward speed is toward the front of the robot.
- Positive speed for either wheel means forward wheel motion.
- RobotConfig motor and encoder signs translate the physical wiring to these
  conventions.

Grid coordinates

- GridCell.column increases with world x.
- GridCell.row increases with world y.
- OccupancyGrid.cell_center() gives the world coordinates represented by a
  cell.
- GridPlanner uses four-neighbor motion: one row or one column per step.


PUBLIC RECORDS


RobotConfig

Import

    from ucsb_xrp import RobotConfig

Construction

    RobotConfig(
        sample_period_ms: int,
        wheel_diameter_mm: float,
        encoder_counts_per_revolution: float,
        track_width_mm: float,
        left_motor_sign: int,
        right_motor_sign: int,
        left_encoder_sign: int,
        right_encoder_sign: int,
        left_start_command: float,
        right_start_command: float,
        left_speed_command_gain: float,
        right_speed_command_gain: float,
        wheel_speed_kp: float,
        max_drive_command: float,
    ) -> RobotConfig

Fields

sample_period_ms: int
    Nominal time between successive Robot.step() samples.

wheel_diameter_mm: float
    Effective rolling diameter used to convert encoder counts to wheel travel.

encoder_counts_per_revolution: float
    Encoder counts for one wheel revolution.

track_width_mm: float
    Effective lateral distance between the left and right wheel paths. This is
    the value used for turning and odometry.

left_motor_sign, right_motor_sign: int
    Each is +1 or -1. The sign converts a positive forward drive command to
    the value required by the corresponding hardware channel.

left_encoder_sign, right_encoder_sign: int
    Each is +1 or -1. The sign makes forward wheel rotation produce increasing
    wheel position.

left_start_command, right_start_command: float
    Magnitude of the drive command needed to begin moving each loaded wheel.

left_speed_command_gain, right_speed_command_gain: float
    Calibrated drive-command change per millimeter per second of requested
    wheel speed.

wheel_speed_kp: float
    Proportional correction applied to wheel-speed error.

max_drive_command: float
    Maximum magnitude returned by WheelSpeedController and accepted by XRPBot.

Compatibility

Projects written before release 0.3 may continue to use the keyword and
read-only property aliases left_start_effort, right_start_effort,
left_speed_effort_gain, right_speed_effort_gain, and max_effort. New projects
use the drive-command names above; specifying both names for one value is an
error.

GridPath

Import

    from ucsb_xrp import GridPath

Construction

    GridPath(
        cells: tuple[GridCell, ...],
    ) -> GridPath

Field

cells: tuple[GridCell, ...]
    Ordered path from start cell through adjacent free cells to destination
    cell. A successful path contains at least one cell.

Method

    to_goals(
        grid: OccupancyGrid,
        final_heading_rad: float | None = None,
    ) -> tuple[NavigationGoal, ...]

Converts the cell path to world-coordinate navigation goals. The start cell is
normally omitted because it represents the robot's current position. The
result contains each later cell at which the path changes direction and always
contains the destination. Cells in the middle of a straight segment are
omitted.

final_heading_rad is applied only to the destination goal. When a path contains
only the start cell, that cell is returned as the destination goal.


SUPPLIED SERVICES


XRPBot

Purpose

Provides the only direct connection between UCSB-XRP and XRPLib. Robot programs
normally use Robot rather than XRPBot.

Import

    from ucsb_xrp import XRPBot

Construction

    XRPBot(config: RobotConfig) -> XRPBot

Methods

    read(include_range: bool = False) -> RawSensors

Reads the timestamp, encoder counts, and USER button. When include_range is
True, the returned sample also contains a range reading when one is available.

    reset_encoders() -> None

Resets both hardware encoder counts.

    wait_for_button() -> None

Returns after a complete USER-button press and release.

    set_drive(command: DriveCommand) -> None

Applies the configured motor signs and sends the two normalized commands to
the hardware.

    set_efforts(efforts: MotorEfforts) -> None

Compatibility alias for set_drive().

    stop() -> None

Sends a zero command to both motors.


Robot

Purpose

Runs the repeated lower-level operations needed by the course programs. Obtain
a Robot with make_robot() so that the component selections in course_setup.py
are used.

Import

    from ucsb_xrp import Robot
    from course_setup import make_robot

Preferred construction

    make_robot(config: RobotConfig) -> Robot

Methods

    start(initial_pose: Pose) -> RobotState

Waits for a USER-button press and release, resets the hardware encoders,
SensorModel, WheelSpeedController, and Odometry, and returns the initial
RobotState. Odometry begins at initial_pose.

    step(
        command: MotionCommand,
        read_range: bool = False,
    ) -> RobotState

Completes one control sample:

1. DifferentialDrive converts command to target wheel speeds.
2. WheelSpeedController uses target and measured wheel speeds to obtain a
   DriveCommand.
3. XRPBot applies that command until the absolute sample deadline.
4. XRPBot reads the encoders and requested range.
5. SensorModel produces Measurements.
6. Odometry updates Pose from the new wheel increments.

The returned RobotState contains the resulting Measurements and Pose.
Robot advances wrap-safe absolute deadlines by sample_period_ms. It reports
the latest positive deadline overrun through last_overrun_ms and skips missed
deadlines rather than accumulating drift or issuing catch-up samples.

    stop() -> None

Stops both motors.

    estimate_range(
        samples: Sequence[float | None],
        minimum_usable: int,
    ) -> float | None

Returns the range estimate produced by the selected
SensorModel.estimate_range() implementation.

Property

    state -> RobotState

Returns the most recent state produced by start() or step().

    last_overrun_ms -> int

Returns how many milliseconds late the latest sample deadline was, or zero
when the deadline was met.


LIVE PROGRAM MODULE

Purpose

Declares a bounded set of values that may be adjusted in the Monitor while a
program runs and publishes compact named intermediate values. The same module
works on virtual and physical targets. It is not a persistent configuration
store or a replacement for telemetry recording.

Import

    from ucsb_xrp import live

LiveParameter

The number(), toggle(), and choice() functions return a LiveParameter. Its
public value property contains the currently applied value:

    parameter.value -> float | bool | str

The declaration fixes the value type and valid set for the life of one run.
Programs read value; they do not assign it directly.

Functions

    live.number(
        name: str,
        default: float,
        minimum: float,
        maximum: float,
        step: float,
        unit: str = "",
        label: str | None = None,
    ) -> LiveParameter

Declares a finite numeric value rendered as a slider. maximum must be greater
than minimum. step must be positive, no larger than the range, and default
must lie on the resulting steps within the inclusive range. The range contains
a whole number of steps. The Monitor sends only representable values.

    live.toggle(
        name: str,
        default: bool,
        label: str | None = None,
    ) -> LiveParameter

Declares a Boolean value rendered as a checkbox.

    live.choice(
        name: str,
        default: str,
        options: Sequence[str],
        label: str | None = None,
    ) -> LiveParameter

Declares a categorical value rendered as radio choices. options contains two
to six distinct short strings, and default must be one of them.

    live.watch(
        name: str,
        value: float | bool | str,
        unit: str = "",
        label: str | None = None,
    ) -> None

Stages or updates one named value for Monitor > Live program. Robot publishes
all staged watches together at its next sample boundary. Numeric values must be
finite; text is limited to 64 characters. Use watches for current modes,
measured or calculated values, and error terms. Use telemetry recording when a
complete time history is required.

    live.apply_updates() -> bool

Applies the most recently queued value for every declared parameter as one
control-loop update and returns True if any applied value changed. Robot.start()
and Robot.step() call this automatically at measured sample boundaries. A
custom loop that does not use Robot calls it at its own explicit boundary.

Names contain only letters, digits, and underscores and begin with a letter or
underscore. A run may declare at most 16 parameters and 16 watch values. A
second declaration of the same parameter name is an error. Parameter updates
are validated on both browser and physical-service boundaries; an invalid or
unknown update does not change the applied value.

DeliveryMission

Purpose

Runs the supplied delivery sequence using the selected sensing, planning, and
navigation components.

Import

    from ucsb_xrp import DeliveryMission

Construction

    DeliveryMission(
        task: DeliveryTask,
        navigation: NavigationController,
        planner: GridPlanner,
    ) -> DeliveryMission

Method

    run(robot: Robot) -> RobotState

Performs the following sequence:

1. Starts robot at task.initial_pose.
2. Requests task.range_sample_count stationary range samples.
3. Uses robot.estimate_range() to set only task.observed_feature_name on a copy
   of task.arena.
4. Creates the occupancy grid specified by the task.
5. Plans from the observation position to task.destination.
6. Converts a successful path to navigation goals and follows them.
7. Stops the robot before returning.

If no path exists, the method stops after planning and returns the most recent
RobotState.

Property

    result -> str | None

None before run(). After run(), the value is:

"delivered"
    Navigation reached the destination.

"no_path"
    GridPlanner returned None.


SELECTABLE COMPONENTS


SensorModel

Purpose

Converts hardware sensor values into measurements in course units and reduces
repeated range readings to one estimate.

Import

    from ucsb_xrp import SensorModel

Construction

    SensorModel(config: RobotConfig) -> SensorModel

Methods

    reset(raw: RawSensors) -> Measurements

Uses raw as the position and time origin. The returned Measurements has zero
wheel positions, increments, speeds, and dt_s. Its range and button fields
correspond to raw.

    update(raw: RawSensors) -> Measurements

Returns measurements relative to the latest reset and the preceding update.
Encoder direction and distance per count come from RobotConfig. dt_s is
calculated with elapsed_time_s().

When no positive time has elapsed, the wheel increments and positions are
still updated, and both wheel speeds are zero.

    estimate_range(
        samples: Sequence[float | None],
        minimum_usable: int,
    ) -> float | None

Discards None values and numeric values that are not finite and positive. If
fewer than minimum_usable values remain, returns None. Otherwise returns the
median of the usable values in millimeters.


WheelSpeedController

Purpose

Converts target and measured wheel speeds to a normalized drive command.

Import

    from ucsb_xrp import WheelSpeedController

Construction

    WheelSpeedController(config: RobotConfig) -> WheelSpeedController

Methods

    reset() -> None

Clears controller state before a new run.

    update(
        target: WheelSpeeds,
        measured: WheelSpeeds,
    ) -> DriveCommand

Returns one command for each wheel. The result uses the corresponding starting
command and speed-to-command calibration, corrects for the
target-minus-measured speed error, and limits each magnitude to
config.max_drive_command.

A target speed of zero produces a zero drive command for that wheel.


DifferentialDrive

Purpose

Converts robot forward speed and turn rate to left and right wheel speeds.

Import

    from ucsb_xrp import DifferentialDrive

Construction

    DifferentialDrive(config: RobotConfig) -> DifferentialDrive

Method

    wheel_speeds(command: MotionCommand) -> WheelSpeeds

Returns wheel speeds corresponding to command at the configured track width.
Equal wheel speeds represent straight motion. Positive turn rate makes the
right wheel speed greater than the left wheel speed. A zero forward speed with
a nonzero turn rate produces an in-place turn.


Odometry

Purpose

Updates the robot pose from measured left and right wheel travel.

Import

    from ucsb_xrp import Odometry

Construction

    Odometry(config: RobotConfig) -> Odometry

Methods

    reset(initial_pose: Pose) -> Pose

Sets the current pose to initial_pose and returns it.

    update(
        left_increment_mm: float,
        right_increment_mm: float,
    ) -> Pose

Uses the two wheel increments and configured track width to update x, y, and
heading. Straight motion, curved motion, and in-place turns use the same
differential-drive model. The returned heading is wrapped to [-pi, pi).

Property

    pose -> Pose

Returns the current pose.


NavigationController

Purpose

Converts an ordered sequence of world-coordinate goals and the current pose to
successive motion commands.

Import

    from ucsb_xrp import NavigationController
    from course_setup import make_navigation_controller

Preferred construction

    make_navigation_controller(
        config: NavigationConfig,
    ) -> NavigationController

Methods

    start(goals: Sequence[NavigationGoal]) -> None

Stores the goals in the supplied order and selects the first one. An empty
sequence is immediately complete.

    update(pose: Pose) -> MotionCommand

Returns the command for the active goal. The controller:

- turns toward a position before driving;
- drives toward the position and reduces speed near it;
- returns to turning if the heading error becomes too large;
- proceeds to the next goal after reaching the current position;
- aligns to heading_rad when the goal specifies one; and
- returns STOP_COMMAND after the last goal is complete.

The thresholds and command magnitudes come from NavigationConfig.

    current_goal() -> NavigationGoal | None

Returns the active goal, or None after completion.

    is_complete() -> bool

Returns True when every requested position and final heading has been reached.


GridPlanner

Purpose

Finds a shortest four-neighbor path through the free cells of an occupancy
grid.

Import

    from ucsb_xrp import GridPlanner
    from course_setup import make_grid_planner

Preferred construction

    make_grid_planner() -> GridPlanner

Method

    plan(
        grid: OccupancyGrid,
        start: GridCell | None,
        goal: GridCell | None,
    ) -> GridPath | None

Returns a GridPath whose first cell is start and whose last cell is goal.
Successive cells are free four-neighbors. The core reference implementation
returns a path with the minimum number of grid steps.

Returns None when either endpoint is None, either endpoint is blocked, or no
free path connects them. When start equals goal and the cell is free, returns
a one-cell path.


FACTORY FUNCTIONS AND IMPLEMENTATION SELECTION

Factory functions are defined in course_setup.py. Program code uses them
instead of constructing selectable implementations by name.

    make_robot(config: RobotConfig) -> Robot

Constructs XRPBot and the selected SensorModel, WheelSpeedController,
DifferentialDrive, and Odometry, then returns the assembled Robot.

    make_navigation_controller(
        config: NavigationConfig,
    ) -> NavigationController

Returns the selected NavigationController implementation.

    make_grid_planner() -> GridPlanner

Returns the selected GridPlanner implementation.

course_setup.py initially selects the supplied implementation of each student
component:

    USE_STUDENT_SENSOR_MODEL = False
    USE_STUDENT_WHEEL_SPEED_CONTROLLER = False
    USE_STUDENT_DIFFERENTIAL_DRIVE = False
    USE_STUDENT_ODOMETRY = False
    USE_STUDENT_NAVIGATION_CONTROLLER = False
    USE_STUDENT_GRID_PLANNER = False

Setting one flag to True changes only the implementation used for that
component. Early challenge starters contain only the flags for components
introduced so far.
